# MVP capability map

Status: implementation ledger, 2026-08-24.

This document tracks delivery; it does not override the contracts. Product
behavior comes from `mvp.md`, human surfaces from `api-cli.md`, desired state
from `blueprint.md`, and implementation seams from `architecture.md`.

## Status vocabulary

- **Contracted**: the authoritative documents agree on the behavior.
- **Console fixture**: the fixture UI demonstrates the interaction, but no
  Controller request exists yet.
- **Scaffolded**: types, routes, or commands exist but do not complete the
  capability.
- **Implemented**: Controller, API, CLI, Console, persistence, and Agent work
  where applicable.
- **Accepted**: automated checks plus the relevant L2 scenario prove the
  capability on the reference topology.

No row is complete at `Console fixture` or `Scaffolded`.

## Active MVP closure order

Work in this order until the L2 MVP journey passes. Start a later item only when
the current item is blocked on an external dependency or a separate writer owns
the later item's files.

1. Close application delivery and public exposure. Submit a Blueprint, apply
   the Environment Compose project through the Agent, deploy and roll back
   `qa-workload/`, and expose its HTTP and WebSocket WebSocket traffic through Caddy and
   Cloudflare Tunnel.
2. Close backing services and Attach. Provision the pinned PostgreSQL and
   Valkey runtimes, attach them to the application, and recover their lifecycle
   after Controller or Agent restart.
3. Close backup and restore. Integrate config, PostgreSQL, and Volume capture,
   upload and verify one Recovery Point, restore it, and prune it safely.
4. Close Runner lifecycle. Complete the native Controller Task executor,
   rootless runtime, dedicated network, retry, and local removal across Console,
   CLI, and API.
5. Close destructive lifecycle. Complete child-first Tenant, Project, and
   Environment deletion with durable retry and parent-last finalization.
6. Run the complete reference-host journey on minimal Ubuntu 24.04. Fix only
   blockers found by that journey, then run the final repository gate.

Do not open a separate MVP lane for broad cleanup, repository-wide review, or
documentation expansion. Update the required contract mirror in the feature
slice and defer other non-blocking work through `docs/issues/`.

## Owner decisions

1. **Resolved 2026-08-20: 1:1 covers operator-facing Controller
   capabilities.** `controller serve`, `controller key show`, `controller etcd
   show`, `agent-run run`, `version`, and `completion` are the closed local
   process/tooling exceptions. Agent enrollment is an operator-facing task and
   follows the 1:1 rule.
2. **Resolved 2026-08-20 (ADR 0016): the native Controller owns the local Agent.** `agent
   join` calls `POST /agents` and receives `202 {task_id}`. The Controller
   creates the Agent record, internally provisions its channel token and
   runtime config, and owns the Agent OCI container through Docker. There is
   no Agent systemd unit, public token endpoint, plaintext bootstrap artifact,
   self-update path, REST pair endpoint, pending approval state, or `agent
   approve` command. mTLS, CAs, and certificates are post-MVP.
3. **Resolved 2026-08-20: connectors are environment-only.** There is no
   project or platform connector, fallback, default marker, stop-propagation,
   or platform connector page. Each backup policy selects a connector owned by
   the same environment; a missing name fails validation.
4. **Resolved 2026-08-29 by ADR 0061: public Component implementations use
   simple names.** The registered MVP implementations are `caddy`,
   `cloudflare-tunnel`, and `coredns`. Controller and Agent remain Host and
   Agent resources and never appear in the Component catalog or projections.
   Owner and apply strategy are separate registry fields; no namespaced-kind
   aliases exist.
5. **Resolved 2026-08-20; source and persistence seam completed 2026-08-23 by ADR 0046: disabled backups may be unconfigured.** A disabled
   backup policy may omit its connector. Enabling requires a connector owned
   by that same environment and fails validation otherwise. The policy is an
   idempotent Environment singleton replacement; stable source records survive
   removal, and only an enabled policy owns the atomic Connector reverse-reference
   fence used by deletion. The canonical field is `frequency`; the Controller
   evaluates the bounded UTC daily/weekly grammar without systemd or a
   subprocess. Encryption remains `age | none`, but config requires `age`.
   Public source records expose stable source and target ids, and current age
   key reads expose recipient, era, creation time, and rotation time.
6. **Resolved 2026-08-20, completed 2026-08-22: service runtime lifecycle is durable operational
   intent.** `runtime_intent` is `running`, `stopped`, or `absent` and is
   never authored by Blueprint. Start, Stop, and Destroy set it; Remove deletes
   desired state. A new Service starts `running`; one Service primary stores
   separately typed desired and runtime subrecords so Blueprint reconciliation
   preserves runtime intent atomically.
7. **Resolved 2026-08-20: release groups have one failure policy.**
   `on_failure` is `switch_back` or `leave_active` and defaults to
   `switch_back` across Console, CLI, API, and Blueprint.
8. **Resolved 2026-08-20: removal boundaries are local.** Runner removal
   deletes only the local container and Groundplane record, never GitHub
   registration. Agent removal stops assignments, aborts active tasks with
   `agent_removed`, revokes the token, waits for offline, and removes the local
   container and records.
9. **Resolved 2026-08-20: Blueprint submission inputs are explicit.** Ordered
   repeatable Compose sources, explicit non-secret variables, reorderable
   Console sources, and deterministic multipart part identities are required.
10. **Resolved 2026-08-21: the human-surface operation contract is
    normalized.** Console action ids and OpenAPI `operationId` values use one
    lowercase `noun.verb` identity. Reads and updates return `200`, creates
    return `201`, Task dispatch returns `202`, and synchronous bodyless delete
    returns `204`. Entity edits use `PATCH`, rename uses `POST /{id}/rename`,
    Component operations use stable ids, Attach takes explicit service and
    backing-service operands without a detail route, and the CLI includes
    `agent config show` and `task events`.
11. **Resolved 2026-08-22 (ADR 0033): Environment IPAM and Runner isolation
    use separate scopes.** Machine bootstrap fixes non-overlapping
    `environment_pool` and `system_pool` CIDRs. Every Environment reserves a
    globally exclusive child pool and every immutable Zone consumes one child
    subnet. Tenant and Project Runners share a five-record Tenant quota, while
    every Runner receives a dedicated `/29`, host UID, and rootless Docker
    daemon and never receives the host Docker socket or joins workload networks.
12. **Resolved 2026-08-23: Entry deletion finalizes exact applied
    materialization before state.** Applied Entries use a 120-second Agent Task;
    never-applied Entries use a 30-second Controller Task. The Entry stays
    visible until success, failure retains it for retry, env files are rewritten
    from pinned remaining generations, and removal never recreates Services.
13. **Resolved 2026-08-23 (ADR 0023): Task-event SSE is sequence-resumable.**
    The public event is the exact operator-safe durable step transition, strict
    `Last-Event-ID` resumes after its sequence, snapshot/watch handoff and
    compaction recovery preserve ordering, terminal Tasks receive a fixed-revision
    final drain, and post-header failures close without leaking diagnostics.

## Open product decisions

These are contract conflicts, not implementation TODOs. Do not choose a shape
without owner approval.

1. **Blueprint release-group shape.** Choose one closed extension shape and
   remove the competing singular/map forms without a compatibility reader.
2. **Durable record details.** ADR 0053 is now Accepted and locks the
   parent-last aggregate deletion contract for its stated MVP scope. ADR 0013
   and ADR 0049 retain their recorded statuses and dependencies. Hierarchy
   records, the existing Task primary/index codecs, and the deletion tombstone
   key are implemented; Secret has a typed destructive finalizer. The
   remaining resource finalizers, immutable Task ownership/index additions,
   and observed-state contract still require executable implementation and
   acceptance evidence before the affected higher-level capabilities are
   accepted.
   ADR 0053 Amendment A also makes `environment.delete` a fourth aggregate
   target in the shared deletion engine. ADR 0025 supplies its Environment
   directory effect; it does not define a parallel deletion schema. C04's
   deletion implementation remains pending until the typed dependency set,
   durable finalization, restart/failure behavior, and host evidence execute.
3. **Execution and apply details.** ADR 0009 remains Proposed for the general
   typed execution catalog. ADR 0015 is superseded by accepted ADR 0061; its
   CoreDNS-specific Agent payload is not an implementation target. Accepted
   ADR 0024 retains C16 source, scheduling, Recovery Point, retention, key,
   deadline, cleanup, and operator invariants. Accepted ADRs 0047 and 0048
   supersede only its artifact/canonical-format, upload-checkpoint, Config
   restore-publication, Agent staging/recovery, and Backup-only terminal-receipt
   clauses with the final schema-1 contract. Acceptance is a contract decision;
   schema, runtime implementation, and acceptance evidence remain pending.
4. **External network resolution grammar.** Rendering can consume an explicit
   stable external-network identity, but the authored `x-gp-network` reference
   and Controller ownership resolver are not yet fully typed end to end.
5. **Resolved 2026-08-23 (ADR 0044): live Host health.** Linux sources, uptime,
   binary units, normalized CPU load, whole percentages, safe Docker/etcd
   failure projection, and the durable-or-bootstrap Agent view are fixed and
   production-composed without persistence or Console fixture fallback.
6. **Idempotent intent encoding.** ADR 0019 is Accepted, and its versioned
   typed canonical value, protected digest envelope, constant-time comparison,
   durable marker repository, and bounded collector are implemented. Agent
   enrollment is the first protected HTTP route with same-transaction Task and
   marker creation; the remaining mutation routes still require integration.
7. **Initial Agent enrollment projection.** The Controller-owned optional
   bootstrap image source, fixed generated config defaults, immutable
   enrollment Task link, durable first-Ready timestamp, pending enrollment
   phase, and nullable live telemetry are locked and implemented through the
   durable aggregate, API projection, and Console store. `POST /agents` now
   creates its protected idempotent Controller Task from bootstrap config, and
   `agent join` dispatches it without exposing credentials.
8. **Resolved 2026-08-23: Entry edit replay lookup uses the stable target.**
   `PATCH /entries/{id}` publishes an Entry replay-target locator in the same
   transaction as the Environment-scoped marker, replacement primary, and new
   immutable generation. Replay resolves the locator before target access;
   every literal is represented only by its SHA-256 digest in protected intent.
9. **Resolved 2026-08-23, amended 2026-08-29 (ADR 0039): immutable Task
   ownership and hierarchical visibility.** One immutable platform-or-Tenant
   owner tuple selects exactly one workspace index, with a second Environment
   index only for Environment-owned Tasks. Platform Activity is global and may
   narrow by Tenant, Project, or Environment; Tenant Activity begins at its
   subtree and may narrow by Project or Environment. Platform Components Tasks
   remains `workspace=platform`. No filter can broaden its surface, and neither
   surface filters by execution target or Component.
10. **Resolved 2026-08-23 (ADR 0041): public Task abort identity and
   delivery.** Abort targets and terminalizes the existing Task, returns that
   same Task id, atomically advances owned resource lifecycle, and uses
   generation-fenced Agent delivery or exact native Controller cancellation.
11. **Resolved 2026-08-28 (ADR 0058): Service Remove is candidate-based desired-state
   publication.** Backing and Component-generated Services cannot be removed
   through the direct Service endpoint. Routes, Attaches, and dependent Services
   block removal; owned Volume mounts and dependency-plan membership are removed
   from the candidate. The current Service and desired head remain authoritative
   until the targeted Agent removal succeeds, then the Controller atomically
   publishes the sealed candidate and deletes Service identity. Failure preserves
   current state and releases the Environment mutation fence so the operator can
   issue a fresh protected removal attempt.
12. **Component Capability cutover (ADR 0061).** The owner has locked a closed
   build-time registry, compiler-isolated Component SDK and registered-planner
   modules, generic typed Groundplane Capabilities, REST/OpenAPI as the external
   machine boundary, CLI as human-only, immutable capability planning, atomic
   Groundplane-owned publication, management ownership distinct from product
   ownership, and secret-reference-only access. Current `internal/components`,
   config maps, Caddy/CoreDNS-specific Agent payloads, cross-component kind
   inspection, and kind-shaped Router projections do not satisfy that contract.
   Routes remain desired state with observed state `unserved` while the sole
   Environment `http-router` entry point is disabled. Route create and edit
   return the resource plus a Controller Task; enabling or disabling the router
   reconciles or removes only the entry point. Caddy retains typed
   `caddyfile_template` implementation configuration. The Agent resolves sealed
   action ids through its matching compiled catalog. Managed resources appear
   on their owning Component detail and only as marked nodes in topology views.
   Blueprint Components use capability keys with portable `settings` and a
   strict implementation-selected `implementation_config`. Controller and
   Agent are not Components. No compatibility form is accepted.

## Unified Blueprint final-publication contract correction (2026-09-02)

ADRs 0051 and 0062 plus the Blueprint grammar now require one final Environment
Blueprint publication envelope for every legal extension combination. Each
comparison, success, and failure arm is bounded by the configured etcd maximum
of 256 operations, and the actual protobuf request is bounded by 1 MiB. The
derived 512 selected-arm and 768 full-request counts are diagnostics, not
rejection limits. Ordinary non-Blueprint `Store.Transact` retains its
96-selected-operation protection; staging, sealing, and non-final-publication
limits are unchanged.

eleven-Release/two-hook/two-physical-source QA Blueprint, `44/98/44` for the

proof that the non-Blueprint 96-operation protection is unchanged. Every
operation is distinct and required for atomic desired-head, Task, marker,
Release, Script, source, Attach, and Backup authority.
